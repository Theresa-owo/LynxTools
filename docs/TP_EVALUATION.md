# 原版 /tp 权限接管评估

本版没有覆盖 `/tp` 或 `/teleport`，没有新增一个看似接管却未生效的权限节点。

## 结论

不建议重写原版 tp 的全部参数解析和执行逻辑。它包含坐标、相对/局部坐标、实体选择器、目标实体、朝向、facing，以及与 execute 上下文协作的形式；复制实现容易遗漏和随版本漂移。

若后续确定需要统一权限，应保留原版命令树、执行器与补全，针对固定 MC/NeoForge 版本替换权限入口。可评估在原版注册权限 predicate 的位置做精确适配，避免维护第二套 tp。

## 必须处理的边界

- `/tp` 重定向到 `/teleport`，两入口都需要一致授权，避免别名绕过。
- 原版选择器有独立检查与补全条件；仅允许 root 不一定让非 OP 获得完整原版参数能力。需要明确选择器权限政策，不能全局提升玩家权限。
- 玩家当前 LP 上下文与控制台/RCON/命令方块政策必须分开声明，不静默用 OP 兜底。
- 模块关闭时是恢复原版授权还是完全禁用，需要定义；不能让旧命令树缓存继续暴露管理入口。
- 原版 tp 允许不安全目标，若保持“功能不变”，不应擅自套用 tpr/home/warp 的安全搜索。
- 覆盖权限后需要逐类参数、选择器、别名、execute 来源、权限撤销和 Tab 的专门回归。

因此建议把它作为一个独立、可审核的小阶段完成；当前先交付已测试的附加传送请求系统。
